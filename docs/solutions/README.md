# Lessons from mistakes (docs/solutions)

Mistakes made while building Formalka Next are written down, so the next session does not repeat them. Three layers:

1. **One file per solved problem** in this folder, named `YYYY-MM-DD-slug.md`. Its frontmatter carries:
   - `rule`: one line, an instruction;
   - `kind`: one of `content-safety`, `legal-source`, `engine`, `reader`, `ui-design`, `accessibility`, `testing`, `evidence-wording`, `tooling`, `process`;
   - `files`: the repository paths it concerns, as globs (`**` any depth, `*` within one folder);
   - `check`: the test or lint that now catches it (`path::what`), or `none: why`;
   - `date` and `commits`.

   The body gives the problem, the cause, the fix, and how it is caught now.
2. **The index** (`INDEX.md`): one line per lesson, generated by `node tools/lessons/index.mjs`.
   - It is **not** loaded at session start: it is not in `CLAUDE.md` or `.claude/rules`.
   - It has a size limit (12,000 characters). Past it, merge similar lessons or move old ones to `archive/`.
3. **The slice:** `node tools/lessons/slice.mjs <paths>`, or `--staged`, or `--diff <ref>`.
   - It prints only the rules whose `files` match the work at hand.
   - Paste the output into the task's prompt, including a subagent's prompt. A rule in the prompt is applied more reliably than one somewhere in the context.
   - The text this design came from (a post the owner shared on 16.10.2026) reports 40 of 40 rules applied when pasted into the prompt, against 45 of 68 escaped errors whose rule *was* in context. **This is their measurement, not ours.**

**Prefer a check to a rule.** If a test or a lint can catch the mistake, write that check; the agent cannot skip it. `index.mjs` lists the lessons that still have `check: none`, as candidates.

**When to write a lesson:** after fixing a mistake that cost a failed test, a wrong claim, a reverted change or a reviewer's finding, and that could happen again. A one-off typo does not need a lesson.

**The pre-commit hook** (`.githooks/pre-commit`):
- it fails when the index is stale, over its limit, or a lesson's check file is missing;
- it runs the docs lint;
- it prints the slice for the staged files.
